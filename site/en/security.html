Security model

FAV reduces common setup mistakes, but it cannot make remote administration risk-free. Its safeguards are designed to fail visibly and preserve a recovery path.

Server identity

On first connection, FAV shows the server’s SSH host-key fingerprint. After you confirm it, the fingerprint is pinned for that host and port. A later mismatch blocks the connection instead of accepting the new key silently.

The first confirmation is only useful when you compare it with an independent source, such as the provider console.

Credentials and keys

  • SSH passwords stay in memory for the current operation and are not saved in the app database.
  • App-generated SSH private keys use the operating system’s secure storage.
  • Local structured data uses encrypted storage whose key is held by the operating system.
  • Diagnostics are scrubbed to remove passwords, private keys, pre-shared keys and server-identifying values.

A WireGuard profile contains a private key. Sharing its file, QR code or clipboard content gives the recipient access as that peer. Revoke the peer if the profile is exposed.

Encrypted backups

Portable backups use a password you supply, Argon2id key derivation and authenticated AES-256-GCM encryption. They include the local SSH identities and peer profiles needed to restore FAV on a clean device, so the backup file remains sensitive even though it is encrypted.

Restore verifies reachable servers. If the old device was lost or compromised, you can replace FAV’s SSH keys and, after two confirmations, revoke all existing peers on those servers. Offline servers remain pending until you retry. Do not operate the same restored data concurrently on multiple devices.

SSH hardening

Hardening is optional. Before disabling root and password login, FAV checks that the management account can connect using its key. It validates the SSH configuration, keeps a backup and attempts rollback if the change fails.

Keep your own SSH key and the provider console. FAV’s anti-lockout checks cannot prove that you still possess an external private key.

What FAV cannot prove

  • A generated profile does not prove that another app installed its routes correctly.
  • A handshake does not prove that all traffic or DNS uses the tunnel.
  • A profile does not provide protection after the VPN client stops.
  • Your server operator can still observe network metadata. A personal VPN is not anonymity from the hosting provider.
  • Script hashes detect changes from the bundled baseline. They do not prove that an arbitrary third-party binary is trustworthy.

Read the repository’s complete security model and security testing record for technical detail.

Report a vulnerability

Do not open a public issue. Use GitHub’s private vulnerability-reporting form so details are not disclosed before a fix is available.
