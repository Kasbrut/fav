Support

Start with the error shown in FAV. Most failures happen before provisioning begins and can be resolved without changing the server.

Check these first

  • Confirm the server address, SSH port and username.
  • Open the SSH TCP port and WireGuard UDP port in both provider and host firewalls.
  • Confirm that package repositories are reachable from the server.
  • If the host key changed, verify the new fingerprint through the provider console before updating it in FAV.
  • If the VPN is active and the server becomes unreachable, disconnect the tunnel before retrying a management operation.

Diagnostics

Use the app’s sanitized diagnostic export when reporting a problem. Read it before attaching it: custom script output or text pasted manually may still contain identifying information.

Never share WireGuard configuration files, QR codes, private keys, pre-shared keys or the contents of /etc/wireguard.

Installation recovery

If provisioning was interrupted, reopen the server in FAV and use installation recovery. Do not delete files under /opt/wg-installer, /var/lib/wg-installer or /var/log/wg-installer until you have confirmed that no installation run is active.

If SSH access is lost, use the provider console. A local factory reset cannot repair remote SSH or firewall configuration.

Restore on another device

Import a .favbackup only into a clean FAV installation. Internet access is required because restore checks every server it can reach. Servers that are offline remain pending and can be retried later from Backup and restore; removing a pending server locally also removes it from that list.

If the old device may be compromised, select SSH-key rotation. Peer cleanup is a separate destructive option and requires two confirmations. Keep your provider console and an independent SSH key available throughout recovery.
