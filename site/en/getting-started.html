Set up your first server

Start with a server you can rebuild. Keep its provider console open until the VPN and your independent SSH access have both been tested.

Use a dedicated server

FAV changes SSH, firewall, forwarding and WireGuard configuration. Do not install it on a host carrying unrelated services or data you cannot afford to disrupt.

Prepare the server

  • Use a maintained Debian or Ubuntu release with kernel 5.6 or newer, systemd, Bash and APT.
  • Have the server address, SSH port, username and password ready. A non-root account must have sudo access.
  • Allow the SSH TCP port and your chosen WireGuard UDP port in the provider firewall. The default WireGuard port is 51820.
  • Keep the provider’s web or serial console available as an independent recovery path.

Install

  1. Add the server in FAV and connect.
  2. Compare the SSH fingerprint with a trusted value from the provider console. Do not approve a fingerprint you cannot verify.
  3. Review the installation options. SSH hardening is optional and disabled by default.
  4. If you enable hardening, add your own SSH public key and test the matching private key independently first.
  5. Start installation and leave the app open when practical. If the connection drops, FAV can recover the detached installation run.

Connect a device

Create a separate peer for each device. A peer profile contains private key material, so treat its QR code and .conf file like a password.

  • For the device running FAV, save the configuration file and import it into WireGuard.
  • For another phone or tablet, display the QR code in FAV and scan it from WireGuard on the destination device.
  • For desktop clients, use the configuration file.

WireGuard mobile clients can be particular about filenames. Keep the exported .conf extension and use a short, ordinary filename.

Verify the result

  • Activate the tunnel and confirm that websites load.
  • Check that your public IPv4 address is the server’s address.
  • Check DNS and IPv6 behavior on the device that imported the profile.
  • Reboot the server and confirm that the tunnel reconnects.
  • Test your own SSH key and provider console before relying on hardened access.

A WireGuard handshake proves that two peers exchanged packets. It does not prove that every route, DNS request or application is protected, and it does not create a kill switch when the tunnel is off.
